## 最值得强调的优势

1. **把“执行成功、可行、审阅通过、报告就绪”拆成四个状态**，避免把运行完成包装成科学成功。
2. **Reviewer 是真正的发布门禁**：已有真实 REVISE 与 APPROVE 两条在线证据，而不是流程图占位。
3. **Quick → Deep 不是复制结果截图**：SourceSnapshot、overlay、artifact lineage 和哈希使工程结果能进入科研链路。
4. **Agent 权限边界可审计**：Deep 工具白名单、Pi capability token、Workspace Grant、Patch Approval 与一次性 WebSocket ticket 形成分层隔离。

## 当前最影响分数的问题

### P0：补齐 Quick Agent 执行器（预计 +3～4 分）

- 实现授权文件枚举、搜索、读取、静态预检、Patch Proposal 的真实执行循环。
- 限制最多两轮，并验证新任务取消替换、重启恢复和人工审批。
- 在右侧工作流显示脱敏工具摘要，但不暴露原始源码、绝对路径或思维链。

### P0：完成独立交付验收（预计 +2 分）

- 干净 Windows 10/11 安装、首次启动、升级、卸载矩阵。
- Authenticode 代码签名与校验说明。
- 用打包后的 App 完成 Quick 2D/3D、Quick → Deep 和 Reviewer 双路径录屏。

### P1：扩展科学案例（预计 +3 分）

- 增加一个真实 3D 工程几何，而不仅是规则网格通路冒烟。
- 冻结材料、载荷、约束和验收阈值；使用独立 FEM 工具复核最终结构。
- 增加至少一个负结果案例，展示系统如何缩小结论适用边界。

### P1：增强多模态表达（预计 +1～2 分）

- 统一展示几何、边界条件示意、密度/应力场、收敛曲线和参数差异。
- 给每张图附 owner、iteration、solver profile 与 artifact hash。
- 不把应力快照当作已完成安全认证。

## 演示答辩建议

- 开场先说“我们解决的是可信实验闭环，不是让大模型替代有限元”。
- 用一次真实 Quick 小网格运行证明产品在算，再用已验证 campaign 讲完整 Reviewer 双路径。
- 主动解释 `completed ≠ feasible` 和 `REVISE ≠ APPROVE`，这是科学价值与稳定性设计的核心加分项。
- 对 Quick Agent 未闭环、未签名和干净机验收待完成要主动披露；诚实边界比展示无法复现的功能更有说服力。
